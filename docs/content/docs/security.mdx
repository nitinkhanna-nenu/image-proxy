## File Access

Ensure that `IMAGE_PROXY_ROOT_PATH` points to a directory containing **only images you intend to serve**. The service should not be exposed to untrusted users who could request sensitive files or cause excessive resource usage through large transformations.

image-proxy includes protections against common attacks like **path traversal** and will refuse to serve files that are not valid images. However, do not rely solely on these protections — deploy the service in a secure environment to minimize risk.

## S3 credentials

Mount a bucket with `IMAGE_PROXY_S3_ACCESS_KEY_ID`, `IMAGE_PROXY_S3_SECRET_ACCESS_KEY`, and, for temporary credentials, `IMAGE_PROXY_S3_SECURITY_TOKEN`. Prefer short-lived STS credentials over long-lived keys. The process does not log those values.

`IMAGE_PROXY_UPLOAD_TOKEN` is a separate application secret. Leave it unset unless something should be able to `PUT` objects into the mount. The token is compared in constant time and is not logged. Put the service behind TLS; an `http://` S3 endpoint sends the access key and security token in the clear.

Give the mounted identity only `s3:GetObject`, `s3:HeadObject`, and, if uploads are enabled, `s3:PutObject` on the one prefix it serves.

## Backend passthrough

`IMAGE_PROXY_BACKEND_URL` is an origin you operate, not a URL taken from the request. The process refuses to forward a path that leaves that origin, including `..` segments and scheme-relative paths. Redirects from the backend are returned to the caller instead of being followed.

The caller's `Authorization` header is forwarded. Do not put credentials in the backend URL, and do not use an `http://` backend when those headers matter.

## Fallback Image

If using the fallback image feature (`IMAGE_PROXY_FALLBACK_IMAGE_URL`), set a reasonable `IMAGE_PROXY_FALLBACK_IMAGE_MAX_SIZE` to prevent abuse. The default limit is 5 MB.

## Deployment Recommendations

- **Run with limited permissions** — Use a non-root user and restrict filesystem access to only the image directory.
- **Place behind a reverse proxy** — Use Traefik, nginx, or Caddy with proper access controls, rate limiting, and TLS termination.
- **Restrict network access** — If possible, limit which hosts can reach the service to your CDN or reverse proxy only.
